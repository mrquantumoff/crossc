## crossc 0.1.1

Driver fixes from a code review aimed at crashes and hangs. Everything else is as in 0.1.0.

* **Sleep, shutdown or removal no longer wait on a Bluetooth channel that is still being opened.** The
  open request now waits outside the driver's power-managed queue, so an open that the Bluetooth stack
  does not cancel can no longer hold up a power transition (in the worst case a 0x9F blue screen, or a
  Driver Verifier break after 60 s).
* **The Bluetooth stack can no longer call into freed driver memory.** Its channel callbacks now go
  through a separately reference-counted block that lives until the stack says it will not call again.
  A channel close that cannot be sent is retried instead of being forgotten.
* **The playback device rejects unreasonable buffer requests.** Audio packet sizes are limited to
  1 ms - 5 s of audio (at most 8 MB) and to four streams at a time. Normal shared and exclusive mode
  requests are unaffected.

Still a pre-release. The new driver code has been checked by review and host tests only, not yet on
hardware; see `docs/SETUP.md` section 13 for what to watch. Unified hardware volume (the buds' own
volume following the Windows slider) is in progress for a later release.
