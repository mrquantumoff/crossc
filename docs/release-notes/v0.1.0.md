## crossc 0.1.0

First release. Galaxy Buds as a Windows playback device over Samsung's SSC codec:
Seamless HiFi (48 kHz / 24-bit) and UHQ (96 kHz / 24-bit).

**Pre-release.** What has run on real hardware (Galaxy Buds4 Pro and Buds3 Pro, Windows 11,
MediaTek RZ616): the Bluetooth channel part of the driver, and live SSC streaming in HiFi and UHQ
through `crossc-cli play`. What has **not** run on real hardware yet: the Windows playback device
in the driver (ACX endpoint and audio hand-off), `crossc-service`, and the installer's install,
uninstall and download paths. They are covered by tests against simulated devices only. Expect
problems, including blue screens; read "Before you install" in the README and keep the recovery
steps in `docs/SETUP.md` (sections 10 and 12) at hand.

### In this release

* `crossc_bth.sys`: driver for the buds' A2DP service (playback endpoint, audio tap, L2CAP pipe).
  Lists product IDs `a013`, `a012`, `a011`; see `docs/MODELS.md`.
* `crossc-service`: streams what Windows plays to the endpoint, in the best mode the buds offer.
* `crossc-installer`: installs and removes the driver and the service; can fetch a release itself.
* `crossc-cli`: `probe`, `media`, `play` (tone, sweep or WAV, with resampling), `raw`.

### Known issues

A code review of the driver found three low-likelihood crash or resource problems that are not
fixed in this release: a slow or stuck sleep/removal while a Bluetooth channel is being opened,
a possible late callback from the Bluetooth stack after a failed channel close, and no upper
bound on the audio buffer size a program can request from the endpoint.
