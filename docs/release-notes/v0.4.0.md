## crossc 0.4.0

**Linux.** crossc now runs on Linux as a PipeWire A2DP codec plugin. BlueZ and PipeWire already
handle the Bluetooth side there, so no driver is needed: the plugin adds SSC to PipeWire's codecs,
encoding with the same `ssc-enc` encoder as the Windows service. Tested on Galaxy Buds4 Pro with
PipeWire 1.6.11: HiFi 48 kHz/24-bit and UHQ 96 kHz/24-bit both play.

```sh
curl -fsSL https://raw.githubusercontent.com/mrquantumoff/crossc/master/linux/install.sh | bash -s -- --uhq auto
```

* Two profiles in the sound settings: **SSC HiFi** and **SSC UHQ 96 kHz**. Switching between them
  takes about a second and needs no restart.
* `crossc-cli uhq auto` switches to UHQ while audio above 48 kHz plays and back to HiFi after 10 s
  without it (a systemd user service). `uhq on` and `uhq off` choose one, `uhq` shows the status.
  While UHQ plays, PipeWire runs at 96 kHz even with other streams open, so 96 kHz audio is not
  resampled through 48 kHz.
* `crossc-cli update` installs a newer release of the plugin and `crossc-cli` from GitHub.
* Stock PipeWire works: the plugin uses the LC3plus codec slot that distributions leave empty.
  `linux/patches/pipewire-ssc.patch` gives PipeWire SSC codec ids of its own.
* The bitrate adapts to the link as on Windows (HiFi 229/192/128/88, UHQ 584/291/152 kbps).
* Release asset: `crossc-linux-0.4.0-x86_64.tar.gz` (plugin for both slots, `crossc-cli`,
  `install.sh`), with its `.sha256`. Built for PipeWire 1.6.11; for another version build from
  source (`install.sh --from-source`).

See `linux/README.md`. The adaptive bitrate on a congested Linux link has not been tested yet.

**Windows.** No functional changes from 0.3.0; the driver and service report version 0.4.0. UHQ
through the Windows playback device is still a known issue (`docs/SETUP.md` section 17).
