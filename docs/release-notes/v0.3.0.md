## crossc 0.3.0

**Tray app.** `crossc-tray` sits in the notification area and shows what the stream is doing:
mode, sample rate and bit depth, bitrate, media MTU, connection state and the last warning. Click
the icon for the details card; right-click for Copy details, the service log folder and Start with
Windows. Buds that are not connected are not shown. The installer installs it, starts it for the
signed-in user, sets it to start at sign-in and adds **crossc tray** to the Start menu.

**Adaptive bitrate.** When the Bluetooth link gets congested, the service steps the SSC bitrate
down and steps back up once the link has been clean for a while:

| Mode | Steps (kbps) |
|---|---|
| HiFi 48 kHz | 229, 192, 128, 88 |
| UHQ 96 kHz | 584, 291, 152 |

* On by default. Registry value `AdaptiveBitrate` = 0 keeps a fixed rate (see `docs/SETUP.md`
  section 15). `HifiBitrate` / `UhqBitrate` choose the top step.
* HiFi now starts at 229 kbps (192 in 0.2.0). `HifiBitrate` = 192 restores the old rate.
* A configured rate the buds do not decode is lowered to the nearest one they do, with a warning
  in the log. UHQ 886 and 442 kbps were measured silent on Buds4 Pro and Buds3 Pro.
* `crossc-cli play --adaptive` runs the same controller from the command line.

**Format selection.** The service reads the format chosen for the buds in Windows sound settings
and makes it the driver's default format (driver/service protocol 4: install the driver and the
service from the same release). The driver feeds the service from the stream that is actually
running when Windows has more than one open.

**Dependencies** updated to their latest releases; building from source needs Rust 1.89 or newer.

### Known issue: UHQ through the Windows device

Choosing *24 bit, 96000 Hz* in sound settings does not yet give UHQ: Windows keeps rendering at
48 kHz, so the buds get HiFi 48 kHz/24, and the service logs "Windows still renders at 48000 Hz/24
although the driver default is now 96000 Hz/24". Restarting the device did not change it. UHQ
itself works with `crossc-cli play` (stop the service first). A fix is being worked on.

### Updating from 0.2.0

The 0.2.0 installer's **Download and install** does not know the tray: run the 0.3.0
`crossc-installer.exe` from the bundle and press **Install** once.

Still a test-signed driver: read "Before you install" in the README.
